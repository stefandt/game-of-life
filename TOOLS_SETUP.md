# Tools Setup Guide

Complete installation and configuration guide for the project toolchain.
Written based on real setup experience — includes known issues and fixes.

---

## Quick overview

| Tool | Purpose | Config in project |
|---|---|---|
| LLVM / Clang | C++ compiler | `CMakePresets.json`, `cmake-kits.json` |
| CMake ≥ 3.24 | Build system generator | `CMakePresets.json` |
| Ninja | Build executor | `CMakePresets.json` |
| VS Build Tools | MSVC runtime + Windows SDK | `cmake-kits.json` (via `setup_kits.ps1`) |
| VS Code + extensions | Editor, IntelliSense, debugger | `.vscode/` |
| Emscripten (WASM only) | WebAssembly compiler | `CMakePresets.json` (`$env{EMSDK}`) |

---

## 1. LLVM / Clang

**Install:**

```powershell
winget install LLVM
```

**Verify:**

```powershell
clang++ --version
clang --version
```

If the commands are not found after installation, restart the terminal — winget modifies `PATH` but the current shell does not reload it automatically.

**Where it is used:**

- `CMakePresets.json` → `base` preset sets `CMAKE_CXX_COMPILER = clang++`
- `cmake-kits.json` → `compilers.CXX` and `compilers.C` fields (generated by `setup_kits.ps1`)

---

## 2. CMake

**Minimum version: 3.24** (`--preset` support was added in 3.19; this project uses 3.24+ features).

**Install:**

```powershell
winget install Kitware.CMake
```

**Verify:**

```powershell
cmake --version
```

**Known issue: CMake 3.18 on a new machine**

The default VS 2019 installer sometimes ships an outdated CMake 3.18 that does not support `--preset`.
Running `cmake --preset clang-debug` will fail with:

```
CMake Error: Unknown argument --preset
```

Fix: install the latest CMake via winget (command above). The `tools/cmake_with_vsdev.cmd` script
also checks the version at startup and prints a clear error message.

**Where it is used:**

- `CMakePresets.json` — all configure and build presets
- `tools/cmake_with_vsdev.cmd` — wraps cmake for terminal builds

---

## 3. Ninja

**Install:**

```powershell
winget install Ninja-build.Ninja
```

**Verify:**

```powershell
ninja --version
```

**Known issue: depot_tools Ninja conflict**

If you have Google's `depot_tools` in your `PATH`, it ships its own `ninja.exe` that is a Linux ELF
binary and does not run on Windows. CMake will pick it up and fail silently.

The `tools/cmake_with_vsdev.cmd` script works around this by finding the first `ninja.exe` in `PATH`
that actually executes, skipping non-working ones.

**Where it is used:**

- `CMakePresets.json` → `base` preset sets `"generator": "Ninja"`

## 4. Visual Studio Build Tools — C++ components

Clang on Windows links against the MSVC runtime and Windows SDK. These must be installed even if
you never use `cl.exe`.

**Install via Visual Studio Installer** (modify an existing installation or install Build Tools):

Required components:
- `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` — MSVC runtime libs (`oldnames.lib`, `msvcrtd.lib`, etc.)
- `Microsoft.VisualStudio.Component.Windows10SDK.22621` — Windows SDK headers and `opengl32.lib` (x64)

Or install Build Tools from the command line:

```powershell
winget install Microsoft.VisualStudio.2022.BuildTools
```

Then open Visual Studio Installer → Modify → Individual Components → add the two components above.

**Known issue: `oldnames.lib` / `msvcrtd.lib` not found**

If Clang can't find MSVC runtime libraries, the build fails at link time:

```
lld-link: error: could not open 'oldnames.lib': no such file or directory
lld-link: error: could not open 'msvcrtd.lib': no such file or directory
```

This means either the C++ tools component is not installed, or the VS developer environment
was not activated. Fix: run `.\tools\setup_kits.ps1` to regenerate `cmake-kits.json`, or
launch builds via `tools/cmake_with_vsdev.cmd` which activates `VsDevCmd.bat` automatically.

**Known issue: `opengl32.lib` not found (x64)**

Windows SDK `10.0.19041.0` (shipped with VS 2019) sometimes only installs x86 OpenGL libraries.
The x64 path `lib\10.0.19041.0\um\x64\opengl32.lib` is missing.

Fix: install a newer Windows SDK:

```powershell
winget install Microsoft.WindowsSDK.10.0.22621
```

Then re-run `.\tools\setup_kits.ps1` to update the kit with the new SDK paths.

**Where it is used:**

- `INCLUDE`, `LIB`, `LIBPATH` environment variables — set by `VsDevCmd.bat` or captured in `cmake-kits.json`
- `tools/cmake_with_vsdev.cmd` — calls `VsDevCmd.bat` before every CMake invocation
- `.vscode/cmake-kits.json` — supplies the same paths to the CMake Tools extension in VS Code

## 5. cmake-kits.json (machine-specific)

`.vscode/cmake-kits.json` is **not committed to git** — it contains absolute paths that differ
between machines, VS versions, and SDK versions.

**Generate it once after cloning:**

```powershell
.\tools\setup_kits.ps1
```

The script finds `VsDevCmd.bat`, captures the environment it sets, and writes a kit file for the
current machine. Works with VS 2019, 2022, Community, Professional, and BuildTools.

Manual equivalent (to inspect what the script does):

```powershell
$vsdev  = (Get-ChildItem "${env:ProgramFiles(x86)}\Microsoft Visual Studio" -Filter "VsDevCmd.bat" -Recurse | Select-Object -First 1).FullName
$output = cmd /c "`"$vsdev`" -arch=x64 -host_arch=x64 >nul 2>&1 && set"
$output | Select-String '^(INCLUDE|LIB|LIBPATH)='
```

**Select the kit in VS Code:**

`Ctrl+Shift+P` → `CMake: Select a Kit` → `Clang + VS <year> <edition> x64`

**Known issue: kit file has paths from another machine**

If you clone the repo on a new machine and use a kit file copied from the old machine, the
`LIB` paths point to the wrong SDK version and the linker cannot find libraries. Always
regenerate with `setup_kits.ps1` on each machine.

## 6. VS Code extensions

**Install:**

```
ms-vscode.cpptools        — C/C++ IntelliSense and debugger
ms-vscode.cmake-tools     — CMake integration, kit selection, build tasks
```

Install from the Extensions panel or:

```powershell
code --install-extension ms-vscode.cpptools
code --install-extension ms-vscode.cmake-tools
```

**Where they are configured:**

- `.vscode/settings.json` — `C_Cpp.default.configurationProvider`, `compileCommands` path
- `.vscode/tasks.json` — build and run tasks
- `.vscode/launch.json` — debug configuration (`cppvsdbg` debugger)
- `.vscode/cmake-kits.json` — active kit (generated by `setup_kits.ps1`)

## 7. Emscripten / emsdk (WebAssembly builds only)

Required only for building the `wasm-release` / `wasm-debug` presets.

**Install:**
if need : winget install Python.Python.3.13
```powershell
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
.\emsdk install latest
.\emsdk activate latest
```

**Activate in every new shell (Windows):**

```powershell
.\emsdk\emsdk_env.bat
```

This sets `EMSDK`, `PATH` (adds `emcc`, `emcmake`, etc.), and other required variables.

**Verify:**

```powershell
emcc --version
echo $env:EMSDK
```

**Build for WASM:**

```powershell
.\tools\build_wasm.cmd
# or for debug:
.\tools\build_wasm.cmd wasm-debug
```

Output: `build/wasm-release/live.html` + `live.js` + `live.wasm`. Open `live.html` in a browser
(must be served via HTTP, not opened as a local file, due to browser security restrictions):

```powershell
cd build/wasm-release
python -m http.server 8080
# then open http://localhost:8080/live.html
```

**Where it is configured:**

- `CMakePresets.json` → `wasm-base` preset uses `"toolchainFile": "$env{EMSDK}/upstream/emscripten/cmake/Modules/Platform/Emscripten.cmake"`
- `CMakeLists.txt` → `if(EMSCRIPTEN)` block sets `PLATFORM=Web`, output suffix `.html`, `--preload-file` and linker flags

## First-time setup checklist

```
[ ] winget install LLVM
[ ] winget install Kitware.CMake
[ ] winget install Ninja-build.Ninja
[ ] Visual Studio Installer → add VC.Tools.x86.x64 + Windows10SDK.22621
[ ] .\tools\setup_kits.ps1       (generates .vscode/cmake-kits.json)
[ ] VS Code: CMake: Select a Kit → Clang + VS <year> <edition> x64
[ ] cmake --preset clang-debug   (verify configure works)
[ ] cmake --build --preset clang-debug
[ ] .\build\clang-debug\live_d.exe
```

For WebAssembly (optional):

```
[ ] git clone https://github.com/emscripten-core/emsdk.git
[ ] emsdk install latest && emsdk activate latest
[ ] emsdk_env.bat
[ ] .\tools\build_wasm.cmd
[ ] cd build\wasm-release && python -m http.server 8080
```
